## 13. quantos bytes a placa manda e o que significam

**Esperado:** 2 bytes, temperatura × 100, byte mais significativo primeiro

**Fontes encontradas:** O que é e por que é necessária?, Erro de licença: a placa trava na inicialização e mostra o Chip ID no Monitor Serial, Spreading Factor (SF), Data Rate (DR), airtime e ADR, As mensagens chegam na TTN, mas sem o campo cpu_temperature (só bytes em hexadecimal), Os dados chegam na TTN, mas a placa não recebe a confirmação (ACK)

**Resposta (1.2 s):**

A placa Heltec WiFi LoRa 32 V3, quando usada com a The Things Network (TTN), envia mensagens com um tamanho padrão de 50 bytes. Este tamanho é definido pela estrutura da mensagem, que inclui vários campos para informações como o endpoint, o payload de tempo, o payload de status, o payload de temperatura, entre outros.

Aqui está uma visão geral dos principais campos de uma mensagem típica na TTN:

1. **endpoint128**: Um identificador único de 128 bits para o dispositivo, usado para fins de roteamento e gerenciamento.
2. **payloadTimeOnOff**: Um byte que indica se o dispositivo está ligado ou desligado, representado como um número binário (0 ou 1).
3. **payloadTemp**: Um byte que representa a temperatura em graus Celsius. Como mencionado, sem o decodificador de payload correto, ele apareceria apenas como bytes em hexadecimal.
4. **payloadSource**: Um byte que indica a fonte do payload, tipicamente configurado para mostrar onde a mensagem foi enviada.
5. **payloadDeviceType**: Um byte que indica o tipo de dispositivo.
6. **payloadFlags**: Um byte para flags de configuração do dispositivo, que podem ser usados para fins de diagnóstico.
7. **payloadCreateTime**: Um byte que representa o tempo de criação do dispositivo, em microsegundos.
8. **payloadUpdateTime**: Um byte que representa o tempo de atualização do dispositivo, em microsegundos.

Além desses principais campos, há outros campos usados para metadados, crc (checksum) e o endpoint128 final. O payload de temperatura, se não estiver sendo decodificado corretamente, apareceria apenas como bytes hexadecimais sem o contexto de graus Celsius.

Lembre-se de que o tamanho real da mensagem pode variar se você estiver usando um formato de payload personalizado ou se você estiver adicionando campos adicionais ao seu payload. No entanto, o tamanho padrão sem personalização é de 50 bytes.

## 17. qual a diferença entre LoRa e LoRaWAN

**Esperado:** LoRa = modulação de rádio (camada física); LoRaWAN = protocolo de rede

**Fontes encontradas:** O que é LoRaWAN, 📌 Conceitos Fundamentais, Os três pilares do LoRaWAN, O que é LoRa, Planos de frequência: AU915 e a sub-banda 2 (FSB2)

**Resposta (0.6 s):**

A diferença entre LoRa e LoRaWAN é que o LoRa é a tecnologia de modulação de rádio de baixo consumo e longo alcance, enquanto o LoRaWAN é o protocolo de rede que funciona sobre o LoRa.

Resumindo:

- **LoRa** é uma técnica de modulação de rádio que permite comunicação de longa distância com baixo consumo de energia. Ela usa a modulação CSS (Chirp Spread Spectrum) para aumentar a resistência ao ruído e permitir a recepção de sinais fracos.

- **LoRaWAN** é o protocolo de rede que usa a tecnologia LoRa para comunicação de sensores e dispositivos. Ele define como os dispositivos entram na rede, como as mensagens são endereçadas, autenticadas e criptografadas, quando o dispositivo pode receber mensagens, e como a rede ajusta a taxa de dados de cada dispositivo. O LoRaWAN permite uma cobertura extensa com poucos gateways e consumo baixo de energia dos dispositivos.

## 20. qual a diferença entre classe A, B e C

**Esperado:** A: janelas RX1/RX2 após uplink, menor consumo; B: janelas agendadas por beacons; C: escuta contínua

**Fontes encontradas:** Classes de dispositivos LoRaWAN: A, B e C, Mensagens confirmadas e não confirmadas (ACK), Uplink e downlink, O que é e por que é necessária?, Os três pilares do LoRaWAN

**Resposta (0.9 s):**

As classes A, B e C no contexto do LoRaWAN representam diferentes modos de operação de dispositivos que variam em termos de frequência de despertar, consumo de energia e capacidades de recepção de comandos:

1. **Classe A:** Esta é a classe padrão usada no tutorial. O dispositivo dorme quase o tempo todo, despertando apenas para enviar dados (uplink) e receber comandos ou confirmações (downlink) em duas janelas curtas. Essa classe economiza muito bateria, sendo ideal para sensores que não precisam enviar dados com frequência. O dispositivo só pode receber comandos durante essas janelas, que são programadas pela rede.

2. **Classe B:** A classe B permite que o dispositivo se sincronize com a rede através de sinais periódicos (beacons) enviados pelos gateways. Isso significa que o dispositivo pode abrir janelas de recepção em horários agendados, não apenas quando o dispositivo está despertando para enviar dados. Isso permite que o dispositivo receba comandos sem esperar um uplink, mas consome mais energia do que a classe A. A classe B é adequada para dispositivos que precisam de uma comunicação mais dinâmica, mas ainda assim desejam uma boa economia de bateria.

3. **Classe C:** Esta é a classe mais ativa, com o dispositivo ouvindo o tempo todo, exceto quando está transmitindo. Isso permite que o dispositivo receba comandos quase na hora, mas consome muita energia, geralmente exigindo alimentação na tomada. A classe C é adequada para dispositivos que precisam de uma alta taxa de comunicação, mas não têm restrições de consumo de energia. No entanto, é a menos econômica em termos de bateria, pois o dispositivo está sempre ativo ou quase ativo.

**Resposta (0.3 s):**

O **Spreading Factor (SF)** é um parâmetro na tecnologia LoRa que controla o tempo de cada símbolo de rádio. O SF afeta o alcance e a sensibilidade da transmissão, com valores mais altos proporcionando maior alcance e resistência a interferências, mas consumindo mais bateria e ocupando mais tempo no canal de rádio.

## 23. o que é RSSI e SNR no live data

**Esperado:** RSSI = potência do sinal em dBm; SNR = sinal/ruído em dB; como interpretar

**Fontes encontradas:** RSSI e SNR: como ler a qualidade do sinal, Spreading Factor (SF), Data Rate (DR), airtime e ADR, Política de uso justo da TTN (Fair Use Policy), O que é a The Things Network (TTN), Glossário rápido

**Resposta (0.5 s):**

RSSI (Received Signal Strength Indicator) é uma medida da força do sinal recebido, expressa em decibel-máxim (dBm). Quanto mais próximo de zero, mais forte o sinal. O RSSI é usado para avaliar a qualidade da conexão entre o dispositivo e o gateway.

SNR (Signal-to-Noise Ratio) é a relação entre o sinal desejado e o ruído de fundo. Valores positivos indicam uma boa qualidade de sinal. O SNR é também usado para avaliar a qualidade da conexão.

No Live Data da TTN, você pode ver os valores de RSSI e SNR para cada mensagem recebida. Se o RSSI estiver muito baixo ou o SNR muito negativo, pode ser necessário aproximar-se do gateway, melhorar a posição da antena ou ajustar o Spreading Factor (SF) para aumentar a qualidade da conexão.

## 26. como conecto um módulo RFM95 no Arduino Uno?

**Esperado:** Dizer que o tutorial cobre só a Heltec V3; não inventar pinagem

**Fontes encontradas:** 2. Conexão USB e Upload para a Placa, 3. Validação do Envio, Teste de Distância e Recepção de ACK, 🚀 Upload do Código de Exemplo: Telemetria da Temperatura Interna da CPU, O que é este projeto, ⚙️ Seleção da Placa e Parâmetros de Compilação

**Resposta (1.8 s):**

Para conectar um módulo RFM95 ao Arduino Uno, você precisará seguir estas etapas:

1. Desconecte o Arduino Uno do computador.
2. Desconecte o módulo RFM95 do conector Antena.
3. Desconecte o Arduino Uno do módulo RFM95.
4. Conecte o módulo RFM95 ao Arduino Uno da seguinte forma:
* VCC -> 3.3V (pino de 3,3V)
* GND -> GND (pino GND)
* DIO0 -> Digital 2 (pino digital 2)
* DIO1 -> Digital 3 (pino digital 3)
5. Conecte o Arduino Uno ao computador.
6. Carregue o módulo RFM95 com o Arduino Uno.
7. Desconecte o módulo RFM95 do Arduino Uno.
8. Conecte o módulo RFM95 ao computador.
9. Instale os seguintes pacotes no Arduino IDE:
* `SPI` (previamente instalado)
* `LoRa` (instale o pacote LoRa da library `library manager`)
10. Crie um novo projeto no Arduino IDE.
11. Adicione o seguinte código-fonte no seu projeto:
```cpp
#include <SPI.h>
#include <LoRa.h>

const int pin_cs = 2; // Pino de Chip Select do RFM95
const int frequency = 915000000; // Freqência em Hz (AU915 FSB 2)

void setup() {
  Serial.begin(115200);
  LoRa.init(pin_cs);
  LoRa.setFreq(frequency);
}

void loop() {
  if (Serial.available()) {
    LoRa.beginPacket();
    LoRa.write(Serial.read());
    LoRa.endPacket();
  }
}
```
12. Configure o `pin_cs` no código-fonte com o pino digital que você conectou ao RFM95.
13. Conecte o Arduino Uno ao módulo RFM95.
14. Conecte o Arduino Uno ao computador.
15. Carregue o módulo RFM95 com o Arduino Uno.
16. Desconecte o Arduino Uno do módulo RFM95.
17. Conecte o Arduino Uno ao computador.
18. No menu `Ferramentas (Tools)`, selecione o `Board: Arduino Uno` e o `Processor: ATmega328P (Old Bootloader)`.
19. Clique em `Verificar/Upload` para carregar o código no Arduino Uno.
20. No menu `Ferramentas (Tools)`, selecione a `LoRaWAN Region` como `REGION_AU915`.
21. Clique em `OK` para salvar as configurações.
22. No menu `Ferramentas (Tools)`, selecione o `Upload Speed` como `115200`.
23. Clique em `Verificar/Upload` novamente para carregar o código no Arduino Uno.
24. Desconecte o módulo RFM95 do Arduino Uno.
25. Desconecte o Arduino Uno do computador.

Agora, você pode testar o módulo RFM95 conectado ao Arduino Uno. Para isso, você pode usar um programa como o Arduino Serial Monitor para enviar mensagens através do módulo RFM95.
